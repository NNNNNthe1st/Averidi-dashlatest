# Independent Dashboard administration diagnostics

Original roadmap requirements 239 (mapping diagnostics), 240 (refresh diagnostics) and 241 (metric diagnostics). The administration surface remains the independent versioned admin API. It uses the existing provider-signed, audience-bound short-lived administrative access token with `dashboard:read`; customer cookies, workspace-owner roles, unsigned tokens and ordinary identity tokens cannot authorize inspection. No website/Analyst integration or impersonation is enabled.

`GET /dashboard/app/api/admin/v1/workspaces/{workspaceId}/datasets/{datasetId}/diagnostics` returns bounded metadata for the active version, or the newest version when no active version exists. Optional `?versionId={id}` selects an explicitly scoped historical or failed version; a foreign or nonexistent version returns 404. Unknown or duplicate query parameters and invalid identifiers return 400. Every successful inspection records `DATASET_DIAGNOSTICS_READ` with the operator identity and dataset/version/analysis IDs. Audit failure fails the inspection. The response is `private, no-store`.

The response shows:

- Dataset/version status, semantic revision, source format/checksum, profile timestamp and row count; up to 20 recent versions identify failed/pending refreshes.
- Up to 100 inferred field names/types/confidence/proposed concepts alongside actual confirmed mappings. Missing profile, missing confirmation, fields absent from the profile, unmapped fields and absent/version-mismatched rules are explicit problem codes. Multiple fields assigned the same concept are disclosed for review, without claiming every duplicate mapping is erroneous.
- Validated confirmed business rules, source connection/check/sync status and sanitized source failure code.
- The matching engine/revision/checksum analysis, current-state marker, built-in metric readiness/refusal, formulas, required concepts, actual mapped input fields and governed definition versions. Numeric metric values are omitted. This is metadata inspection: `sourceBytesVerified:false` explicitly states that the endpoint did not reread the source file or recompute metrics.
- Up to 100 dataset-bound custom formulas with expressions, source version/checksum/revision, saved confirmed basis, governed input definitions/lineage and current-state checks. Preview values and raw filter values are omitted; filter fields/types remain visible. Invalid custom definitions are marked rather than echoed.
- Up to 20 quality checks with up to 100 issue IDs/codes/severities/resolution timestamps per check, with current revision/checksum markers. Source rows, previews, arbitrary quality details and review notes are omitted.

`GET /dashboard/app/api/admin/v1/jobs?workspaceId={id}&status=FAILED&limit=50` inspects failures using the existing cursor-paginated job collection. Workspace and status filters are optional and validated; limits remain 1–100. Results add progress, next availability, cancellation/completion timestamps and `errorCode`. Known connector/authentication/permission/lease/integrity failures remain actionable; arbitrary stored exception text becomes `PROCESSING_FAILED`. No job payload/result, credential, lease token or raw error string is returned. The existing ID/status/attempt/timestamp fields remain present. Follow `nextCursor` using the same filters; there is no automatic retry or mutation in this read workflow.

Both workflows refuse database errors with a fixed service-unavailable code. They neither alter customer mappings/rules nor bypass their calculation refusal. Historical results are explicitly distinguished from current active results; missing or newly changed confirmation cannot be presented as current analysis. Quality descriptions and formula values remain in the existing customer-authorized workflows. Diagnostics use existing tables, so no extra migration, dependency or runtime is needed.

`tests/admin-diagnostics.test.ts` exercises actual PostgreSQL and a TLS-verified local signing provider: access/permission/token-use refusal, metadata projection, native built-in/custom formula lineage, current/stale semantics, scope/query validation, successful read auditing, filtered cursor pagination and arbitrary failure-string redaction. Full regression/build/browser verification is recorded in the architecture progress record for this batch.
